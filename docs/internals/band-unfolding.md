# Band unfolding: implementation

This page describes how {py:func}`~PAOFLOW.models.band_unfold.unfold_bands` and {py:func}`~PAOFLOW.models.band_unfold.unfold_bands_sparse` in `src/PAOFLOW/models/band_unfold.py` evaluate the spectral weights of supercell states: the inputs they read, the steps of the algorithm, the cost, and the sparse route. The physics, from the folding of wavevectors to the weight in an orbital basis, its sum rule and its limits, is derived in [Band unfolding: spectral weights of supercell states](../learn/theory/band-unfolding.md). How to run the two functions is in [How to unfold supercell bands onto the primitive Brillouin zone](../learn/howtos/band-unfolding.md) and [How to unfold the bands of large supercells with the sparse solver](../learn/howtos/unfold-large-supercells.md).

## Inputs

Both functions take one model dictionary per cell, `{'label', 'alat', 'model': {'a_vectors', 'atoms'}}`, with the lattice vectors as rows in Cartesian units of `alat` and each atom's `tau` in the same units. The two dictionaries must use the same `alat`, because the transformation matrix and the atom mapping compare lengths in its units.

The real-space Hamiltonian of each cell comes from `_extract_hamiltonian`, as `HRs` of shape `(nawf, nawf, nR, nspin)`, the lattice vectors `R` of shape `(nR, 3)` (Cartesian, units of `alat`) and the orbital count per atom `norbitals`:

- A tight-binding dictionary (from `EDTBModel.to_model_dict()` or the other model builders) is turned into a Hamiltonian by `_paoflow_runner.build_model_hamiltonian`, which runs the model through PAOFLOW.
- A dictionary from {py:func}`~PAOFLOW.models.band_unfold.paoflow_to_model_dict` carries the projected Hamiltonian of a finished run under the private key `_paoflow` (`HRs`, `R`, `nawf`, `nspin`, `norbitals`, `fourier_sign`). `R` is the FFT grid of `HRs`, built with `get_R_grid_fft` when the run has not built it; the positions are converted from bohr to units of `alat`; `norbitals` is taken from `naw` when the run provides it and is otherwise assumed uniform.

The transform below uses $H(\mathbf{k}) = \sum_\mathbf{R} H(\mathbf{R})\,e^{+2\pi i\,\mathbf{k}\cdot\mathbf{R}}$, the convention of the model Hamiltonians, which store the hopping to $\boldsymbol{\tau}_\beta + \mathbf{R}$. The projected Hamiltonian is `HRs = ifftn(Hks)` and stores it at $\boldsymbol{\tau}_\beta - \mathbf{R}$, so `paoflow_to_model_dict` sets `fourier_sign = -1` and `_extract_hamiltonian` returns `sign * R`. A `_paoflow` dictionary without the entry is classified by `_detect_fourier_sign`, which picks the sign that minimises the bond length weighted by $|H_{\mu\nu}(\mathbf{R})|$, the test of `sparse_hamiltonian.detect_bond_sign`. With the wrong sign the energies are unchanged for a time-reversal-symmetric Hamiltonian, but the weights select the folded branches of $-\mathbf{k}$ ([The mapping of wavevectors](../learn/theory/band-unfolding.md#the-mapping-of-wavevectors); [Slater–Koster and EDTB module](sk-edtb.md)).

Only the first spin channel, `HRs[:, :, :, 0]`, is transformed. A collinear spin-polarised Hamiltonian is therefore unfolded for its first spin channel only.

## Algorithm of `unfold_bands`

1. **Transformation matrix.** `_find_transformation_matrix` solves `a_sc = M @ a_pc` as `M = a_sc @ inv(a_pc)`, rounds it to integers and raises `ValueError` when the largest residual exceeds `1e-6`. $N = |\det M|$.
2. **Translations.** `_find_translations` scans the primitive lattice vectors $n_1\mathbf{a}_1 + n_2\mathbf{a}_2 + n_3\mathbf{a}_3$ with $|n_i| \le \max|M_{ij}| + 1$, keeps those whose fractional coordinates in the supercell lie in $[0, 1)$ (tolerance `1e-6`), removes duplicates modulo the supercell lattice, sorts them lexicographically and checks that there are $N$. The result is `R_translations`, shape `(N, 3)`, Cartesian in units of `alat`.
3. **Atom mapping.** `_build_atom_map` returns `atom_map[alpha, ell]`, shape `(n_at_pc, N)`, the supercell atom at $\boldsymbol{\tau}_\alpha + \mathbf{R}_\ell$ modulo the supercell lattice, matched within `1e-4` in fractional coordinates of the supercell. It raises when a target has no atom, when an atom is claimed twice, and when supercell atoms are left over.
4. **Orbital index table.** The supercell orbitals are stored atom by atom, in the order of `atoms`. For each primitive atom $\alpha$, `orb_idx[alpha]` is an integer array of shape `(N, norb_alpha)` that holds the supercell orbital indices of the copies of $\alpha$, one row per translation; a copy with a different orbital count raises `ValueError`.
5. **Path.** `make_kpath` turns `sym_points` (fractional coordinates of the primitive reciprocal lattice) and `path_str` into Cartesian points `frac @ inv(a_pc).T`, in units of $2\pi/a_\mathrm{lat}$, with `nk_per_seg` points per segment and the end point of each continuous piece (`'|'` starts a new piece). It also returns the cumulative distance `kdist` and the ticks.
6. **Loop over k.** At each point, the primitive and the supercell Hamiltonians are summed as `HRs[:, :, :, 0] @ exp(2j*pi*R @ k)`, symmetrised as $\tfrac12(H + H^\dagger)$ and diagonalised with `numpy.linalg.eigh`. `_compute_spectral_weights` takes the eigenvectors `evecs` (columns) and the phases `uphi = exp(-2j*pi*R_translations @ k)`; for each $\alpha$ it gathers `psi = evecs[orb_idx[alpha], :]`, shape `(N, norb_alpha, nawf_sc)`, contracts `einsum('r,rmn->mn', uphi, psi)`, and adds the squared moduli summed over `m`. The total is divided by $N$. This is the weight of [The weight in an orbital basis](../learn/theory/band-unfolding.md#the-weight-in-an-orbital-basis).
7. **Sum rule.** The largest deviation of $\sum_n w_n(\mathbf{k})$ from `nawf_pc` is printed, and a `UserWarning` is raised above `0.01`. By completeness of the eigenvectors the sum equals the number of mapped orbitals for any phases ([The sum rule](../learn/theory/band-unfolding.md#the-sum-rule)), so the warning fires only when the primitive model has a different orbital count from the supercell atoms mapped onto it. It does not test positions, images or the path.

The function returns an `UnfoldResult`: `kpath_cart`, `kdist`, `sym_ticks`, `E_pc` of shape `(nk, nawf_pc)`, `E_sc` and `W` of shape `(nk, nawf_sc)`, `nawf_pc`, `nawf_sc`, `N`, `R_translations`, `atom_map`, and the lattices `a_pc`, `a_sc`, `M`.

## Images of the supercell atoms

The atom mapping matches positions modulo the supercell lattice, but the phase of the weight uses the reduced translation $\mathbf{R}_\ell$, not the displacement $\boldsymbol{\tau}_I - \boldsymbol{\tau}_\alpha$ of the supercell atom $I$ from its primitive atom. The Bloch sums of the supercell are in the lattice gauge, so an atom stored at $\boldsymbol{\tau}_\alpha + \mathbf{R}_\ell + \mathbf{T}$, with $\mathbf{T}$ a supercell lattice vector, carries an extra phase $e^{2\pi i\,\mathbf{k}\cdot\mathbf{T}}$ in its eigenvector coefficients that `uphi` does not remove. Its weights are then wrong, while the sum rule still holds. In the eight-atom silicon cube of the how-to, moving atom 7 by the lattice vector $(1, 0, 0)$ makes the summed weight of the supercell states at a primitive level differ from its degeneracy by up to 0.72 along L–$\Gamma$–X, with the sum rule exact to $10^{-15}$. The builders of the how-tos place every atom at $\boldsymbol{\tau}_\alpha + \mathbf{R}_\ell$ and are not affected. Taking the phase from `tau_sc[atom_map[alpha, ell]] - tau_pc[alpha]` instead of `R_translations` would remove the restriction.

## Cost

The dense route keeps `HRs` of both cells in memory, $16\,n_\mathrm{awf}^2\,n_R$ bytes per spin channel for the supercell, and at each k-point spends $O(n_\mathrm{awf}^2 n_R)$ on the Fourier sum, $O(n_\mathrm{awf}^3)$ on `eigh` and $O(n_\mathrm{awf}^2)$ on the weights, with $n_\mathrm{awf}$ the number of supercell orbitals. The k-points are processed one after the other; under `mpirun` every rank runs the whole loop and only rank 0 prints.

## The sparse route

`unfold_bands_sparse` repeats steps 1 to 5, builds the primitive Hamiltonian densely as above, and replaces the supercell Hamiltonian with {py:class}`~PAOFLOW.spectrum.sparse_bands.SparseEDTB`. That class evaluates the hoppings of a distance-dependent EDTB model from the bond lengths and keeps them as a list of bonds; `build_hk(k_frac)` assembles a CSR matrix with the phases $e^{2\pi i\,\boldsymbol{\kappa}\cdot\mathbf{T}}$ of the integer supercell vectors, the same lattice gauge as the dense route. The Cartesian path point is converted to supercell fractional coordinates as `k_frac = k @ a_sc.T`. The orbital layout of `SparseEDTB` (`atom_block_start`, `norbitals`) gives the index table of step 4.

`SparseEDTB.eigh_at_k` returns the `n_eigs` eigenpairs nearest `sigma`, with `n_eigs` capped at `nawf_sc - 2`. `_solve_window` diagonalises densely when the cell has at most 1000 orbitals or when `n_eigs` exceeds a third of them, and otherwise calls `scipy.sparse.linalg.eigsh` in shift-invert mode, which factorises $H(\mathbf{k}) - \sigma$; the extra keyword arguments of `unfold_bands_sparse` go to `eigsh`. When ARPACK does not converge it falls back to a dense diagonalisation up to 6000 orbitals and raises `RuntimeError` above. The weights use `_compute_spectral_weights` on the returned eigenvectors. `E_sc` and `W` have shape `(nk, n_eigs)`, `nawf_sc` is set to `n_eigs`, and no sum rule is checked, because the states outside the window are missing ([Partial spectra](../learn/theory/band-unfolding.md#partial-spectra)).

`eigsh` is called with SciPy's default Krylov dimension, and the eigenvectors of a degenerate group are not orthonormalised. The sparse backend does both, because ARPACK can return fewer copies of an exact multiplet than its multiplicity and copies that are not orthogonal ([The eigensolver of the sparse backend](sparse-eigensolver.md)); in the unfolding this would change the summed weight of a multiplet. It has not been measured on this route.

The k-points are distributed with joblib (`backend='loky'` by default) over `n_workers` processes, resolved with `resolve_n_jobs` within the core budget of the MPI rank; processes rather than threads, because the shift-invert solve holds the GIL. The loop runs inside `threadpool_limits(1)` for BLAS. Unlike `SparseEDTB.compute_bands`, which limits `n_workers=-1` to four workers above 5000 orbitals and runs serially above 20000, `unfold_bands_sparse` applies no such cap, so the memory of one factorisation times the number of workers must fit in the node.

Memory is the bond list, which grows linearly with the number of atoms, plus one sparse factorisation of $H(\mathbf{k}) - \sigma$ per worker, whose fill-in grows faster than the number of orbitals. The time per k-point follows the factorisation.
